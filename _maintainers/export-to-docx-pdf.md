# Export wiki pages to .docx or .pdf with pandoc

> **Maintainers only.** Readers who want a PDF of one page can use Obsidian's built-in
> **⋯ → Export to PDF**, which needs no setup.

## TL;DR

```bash
pandoc 05-networking/internet-doesnt-work-runbook.md \
  -f gfm+yaml_metadata_block --resource-path=05-networking \
  -o runbook.docx
```

## When you need this

Someone needs a page (or the whole wiki) as a Word file or a PDF: an offline handout for interns, an attachment to an email, a printed runbook.

## What survives the export, and what doesn't

> [!IMPORTANT]
> Pandoc reads the **raw Markdown file**. It never sees what Obsidian plugins draw on screen.
> Dataview tables, Obsidian Charts, and live Excalidraw/Canvas boards are generated by
> Obsidian at view time, so pandoc gets either a raw code block or nothing.

| In the page                            | In the .docx / .pdf                                               |
| -------------------------------------- | ----------------------------------------------------------------- |
| Headings, lists, tables, code blocks   | ✅ Exported                                                        |
| Image link to an SVG/PNG in `_assets/` | ✅ Exported (PDF needs `librsvg2-bin` for SVG)                     |
| `> [!WARNING]` callouts                | ⚠️ Only with pandoc ≥ 3.1.10; older versions export a plain quote |
| Relative links to other pages          | ⚠️ Exported as links that point nowhere                           |
| Dataview query                         | ❌ Raw code block                                                  |
| Obsidian Charts block                  | ❌ Raw code block                                                  |
| `.excalidraw.md` / `.canvas`           | ❌ Not exported                                                    |
| `[[wikilinks]]`, `![[embeds]]`         | ❌ Literal text (also banned by CONTRIBUTING)                      |

**So graphs belong in exports as images, not as plugin blocks.** The workflow:

1. Draw in Excalidraw; keep the source in `_assets/src/`.
2. Export the drawing as SVG (Excalidraw menu → Export → SVG) into `_assets/`.
3. Link it with a standard image link: `![Layered runbook](../_assets/runbook.svg)`.

The diagram then shows on GitHub, in Obsidian, and in the export. That's why CONTRIBUTING rule 7 exists.

## Commands

> Tested on: **Ubuntu 24.04**

### 1. Install pandoc

```bash
sudo apt install -y pandoc
pandoc --version | head -1
```

> [!NOTE]
> If this prints a version below **3.1.10**, callouts export as plain quotes. Install the
> current release from GitHub instead, which also works on 22.04:
>
> ```bash
> # Note: replace <VERSION> with the latest release from github.com/jgm/pandoc/releases
> wget https://github.com/jgm/pandoc/releases/download/<VERSION>/pandoc-<VERSION>-1-amd64.deb
> sudo apt install ./pandoc-<VERSION>-1-amd64.deb
> ```

### 2. (PDF only) Install a PDF engine

```bash
sudo apt install -y texlive-xetex texlive-fonts-recommended librsvg2-bin fonts-dejavu
```

> [!WARNING]
> This pulls in several hundred MB of LaTeX. Skip it if you only need `.docx`.

### 3. Export one page

To Word, run from the repo root:

```bash
pandoc 05-networking/internet-doesnt-work-runbook.md \
  -f gfm+yaml_metadata_block \
  --resource-path=05-networking \
  -o runbook.docx
```

To PDF:

```bash
pandoc 05-networking/internet-doesnt-work-runbook.md \
  -f gfm+yaml_metadata_block \
  --resource-path=05-networking \
  --pdf-engine=xelatex -V mainfont="DejaVu Sans" -V geometry:margin=2cm \
  -o runbook.pdf
```

- `-f gfm+yaml_metadata_block`: read GitHub-flavoured Markdown, and treat the frontmatter as metadata instead of printing it as text.
- `--resource-path`: where pandoc looks for images. Set it to the page's folder so `../_assets/...` resolves.
- `-V mainfont="DejaVu Sans"`: a font with Cyrillic, so Ukrainian text doesn't come out as blank boxes.

### 4. Export a whole section as one handout

```bash
pandoc 00-start-here/*.md 05-networking/*.md \
  -f gfm+yaml_metadata_block \
  --resource-path=00-start-here:05-networking \
  --toc --metadata title="Ubuntu wiki — onboarding handout" \
  -o handout.docx
```

`--toc` adds a table of contents built from the headings.

## What the output means

A successful export prints nothing and leaves the file. Warnings look like this:

```
[WARNING] Could not fetch resource network-request-journey.svg: replacing image with description

(e.g. a missing image)
```

- `Could not fetch resource ...`: an image path didn't resolve. Check `--resource-path`.
- `Missing character: There is no ... in font`: the font lacks a glyph. Change `mainfont`.

## If it doesn't work

- **Frontmatter printed at the top of the document** → you used `-f gfm` without `+yaml_metadata_block`.
- **Callouts show as `[!WARNING]` in a plain quote** → pandoc is older than 3.1.10. Install the GitHub `.deb`.
- **`xelatex not found`** → step 2 wasn't run.
- **SVG missing in the PDF** → `librsvg2-bin` isn't installed.
- **A Dataview table appears as code** → expected. Pandoc can't run plugins. Replace it with a static table or an exported image.

## Go deeper (L2 / L3)

- **Custom Word styling:** make a reference document once, restyle it in Word, then pass it to every export:

  ```bash
  pandoc -o custom-reference.docx --print-default-data-file reference.docx
  pandoc page.md -f gfm+yaml_metadata_block --reference-doc=custom-reference.docx -o page.docx
  ```

- **Automating the handout:** a tiny script or Makefile that runs step 4 is fine. Don't add it to CI until the wiki has enough pages to justify it (see `NEXT-STEPS.LOCAL.md`).
